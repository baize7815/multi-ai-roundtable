# Multi AI Roundtable v0.2.5（源码更新）

基于 v0.2.4 的游戏后台通信修复和迷雾议会交互梳理。本次同步 GitHub `main` 分支的源码及 `dist/` 可加载构建产物；**不代表已经建立 GitHub Release 或上传发行版 ZIP**。

## 两款游戏：后台发送与回复

- 统一十家 AI 网页的最终回复补认领流程。需符合当前操作的发送基线、完成状态和文本稳定条件，防止旧回答被错误归属到新回合。
- 引入回复终态的持久化收据及按游戏操作归属的确认路径，降低后台重启或回执丢失导致的重复处理风险。
- 私密游戏网页先检查页面和输入框就绪再发送；发送确认不明确时继续观察，不盲目重复点击。发送准备阶段与回复生成分别处理。
- 游戏每个模型操作独立计时：发送未确认且无回复按 180 秒观察，已经进入回复阶段时按 360 秒无进展判断；实际流式活动会更新对应操作的活动记录。
- 后台监听辅助采用网页渲染唤醒与受限的真实焦点短脉冲：只作用于扩展管理的游戏窗口，短暂获得焦点后恢复原 Chrome 窗口，并在全局限频。部分网站仍可能受到 Chrome 或操作系统后台节流影响。
- 游戏开局按钮在初始化时立即显示“中断”，并防止重复开始。侧栏可区分发送中、发送未确认、等待网页回复及回复已开始等状态。

## 迷雾议会：阶段与界面

- 保持现有规则顺序：夜间行动、天亮、可选私聊、公开讨论、提名、指控与辩护、投票和处决。
- 白天私聊阶段的 UI 明确标为“白天·可选私聊（公开发言前）”；说明私人消息仅双方可见，公开发言才对所有玩家可见。
- 人类玩家可以跳过可选私聊，之后仍会进入公开讨论。未变更角色技能、玩家身份权限和游戏胜负判定。

## 自动化验证与限制

- `npm run typecheck`、`npm run test:werewolf`、`npm run test:clocktower`、`npm run build` 通过。
- 增加首次发送防重复、十平台回复恢复、终态归属、游戏操作超时、私密窗口短暂聚焦与焦点恢复、私聊私密回复到公开讨论等回归测试。
- 迷雾议会的完整引擎模拟使用确定性的合法提名行为，避免测试用 AI 无限制造平票；**这不等于真实网页登录的全流程验收通过**。
- **尚未验证**：全部十家真实 AI 网站在长期隐藏窗口中的发送与回复稳定性；不同系统的 Chrome 窗口聚焦可能造成短暂焦点变化，且不能保证绕过平台的后台节流；云端真实备份写入不在本次验证范围。

## 安装

使用 `main` 分支源码执行 `npm ci && npm run build`，在 `chrome://extensions/` 加载 `dist/`。已经本地加载旧版本的用户可以刷新扩展后新开游戏测试；GitHub Releases 的安装包版本请以 Releases 页面实际显示为准。
